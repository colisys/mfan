# MFan

面向 **Intel Mac（macOS 13+）** 的轻量菜单栏风扇控制工具，SwiftPM / Swift 5.8 构建。不支持 Apple Silicon（包括 Rosetta）；SMC 接口具有试验性，不声称支持全部机型。

## 功能

- 菜单栏显示风扇转速、CPU / 电池温度或限时控制倒计时，可选轮询间隔（3–30 秒）。
- 每个风扇独立调速：100 RPM 步进，"不限时"或 30–600 秒限时；可随时改转速或恢复自动，无需等待期限结束。
- 转速自动限制在硬件上下限内；没有手动模式键的旧机型通过临时提高最低转速控制，会记住并恢复原值。
- "启动设定"：分别记住每个风扇的转速，下次打开 MFan 后自动应用一次。"启动设定"与"取消启动设定"并排显示在对应风扇下方，样式一致。
- 全局温控与进程规则统一为连续温度曲线，逐风扇取较高目标，支持全部或指定风扇；详见下方“控制中心与连续温控”。旧规则保留但调速语义升级。
- 内置保养须知（问号按钮）：日常散热建议、清洁注意事项和电池异常提醒。

## 构建与运行

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer sh scripts/build-app.sh --adhoc-sign
open dist/MFan.app
```

## 工作原理

- GUI 不以 root 运行。首次控制时经一次管理员授权，启动临时 `fanctl serve` 特权服务；之后通过 `/tmp/mfan-UUID` 本地 socket 通信，不再重复授权。
- 服务有独立心跳：GUI 每 10 秒续期，60 秒清醒时间收不到心跳就恢复风扇并退出；系统休眠不消耗租期，限时期限跨休眠仍会到期。
- 正常退出、心跳超时或限时到期时，服务都会先还原自己修改过的风扇。不要强杀 `fanctl` 或删除活跃 socket，这会绕过恢复流程。

## CLI

```sh
dist/MFan.app/Contents/MacOS/fanctl status            # 风扇状态 JSON
dist/MFan.app/Contents/MacOS/fanctl set <fan> <rpm> <seconds>   # 30–600 秒，前台等待并负责恢复
dist/MFan.app/Contents/MacOS/fanctl auto [fan]        # 恢复自动，缺省为全部
```

不要同时从终端和其他工具执行控制命令。

## 开发

- `Sources/MFan`：菜单栏界面、授权与 socket 客户端。
- `Sources/FanCore`：SMC 读写、控制协议与心跳租期。
- `Sources/fanctl`：CLI 与临时特权服务。
- `Tests`：socket 通信、心跳/休眠时序、恢复重试（模拟硬件，不写真实 SMC）。

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test
```

构建与测试需串行执行（SwiftPM 构建数据库不支持并行）。更新版本前，先在旧面板恢复自动并正常退出，重新打包不会升级已运行的旧服务。

## 控制中心与连续温控

从菜单栏面板点击 **控制中心** 打开普通窗口。窗口无标题栏，左侧导航栏（概览、温控曲线、规则、设置）为毛玻璃材质，可从顶部空白处拖动窗口、双击缩放；每页一屏，页面放不下时滚动，底部状态栏常驻显示操作状态、错误和“恢复温控接管”按钮。菜单栏面板不再包含规则设置，只显示当前执行的内容：始终列出“全局温控”的启用状态和当前范围百分比，再逐条列出生效中的规则，并提供“打开规则设置”按钮直接跳到规则页。原生 Touch Bar 直接绑定到该窗口，每个风扇一个按钮用来选择，滑块拖动时读数跟随手指，停手约 0.4 秒后才下发转速，未拖动时读数显示实时转速（按刷新间隔更新）；Touch Bar 上“恢复自动”右边还有“恢复接管”，作用与窗口底部的“恢复温控接管”相同。需在系统中选择 App 控制，切换其他 App 后不会占用其 Touch Bar。关闭窗口不会退出 MFan。

- 全局温控默认关闭。在“温控曲线”页拖动三次贝塞尔曲线上的 4 个圆点（起点、两个控制柄、终点），勾选启用后点击“应用温控”。横轴是 CPU 温度，纵轴是风扇在自身转速范围内的比例，0% 并非停转。
- 拖动时会保持曲线单调（温度与比例都不递减），两端至少相隔 10°C。应用时曲线按温度均匀采样为 13 个点再线性插值，超出端点保持端点值；每个风扇按自身硬件范围计算。配置保存在独立的 `thermalConfiguration.v1` 中；旧版折线配置仍可读取，打开时会拟合为贝塞尔曲线。
- 规则的高温目标按“各风扇自身转速范围的百分比”设置（最低到最高转速），不再是统一的绝对 RPM。双风扇机型的 CPU 侧与 GPU 侧转速范围不同，同一条“全部风扇”规则会分别换算成各自的 RPM，界面会逐风扇显示换算结果。
- 旧规则自动沿用已有数据：原 RPM 仍作为固定目标并按各风扇范围截断，界面显示为换算后的近似百分比；拖动该规则的滑块后改为百分比规则。原温度阈值是起温（未设置时为 40°C）；从起温的最低转速逐步升至 `max(100, 起温+20)`°C 时的目标。进程规则仍仅在对应进程运行时参与计算。
- 各规则与全局曲线逐风扇取较高目标。全局开关不禁用规则。每次现有刷新周期重算，变化不足 100 RPM 时保持上次目标，不保证瞬时追踪。
- 手动设定或恢复自动会暂停对应风扇的温控接管；控制中心的“恢复温控接管”重新启用。Touch Bar 同样遵循此行为，不会改变启动设定。
- 温度不可用时释放温控接管，正常退出或服务心跳失联也恢复系统控制。规则结束时，没有全局目标的风扇回到各自启动设定（若有），否则恢复自动。
- Touch Bar 显示与真实硬件调速需实机验证，自动化测试仅验证计算、存储与模拟硬件路径。
